# DPI Changer для Wear OS

Проект из двух модулей.

## 1. `app` — меняет системный DPI (работает без root)

Что делает: приложение-часы со списком пресетов DPI. При нажатии вызывает
скрытый системный API `IWindowManager.setForcedDisplayDensityForUser` —
тот же самый метод, который дергает `adb shell wm density`.

### Установка и запуск

```
adb install app-debug.apk
adb shell pm grant com.zhenya.dpichanger android.permission.WRITE_SECURE_SETTINGS
```

Второй шаг — обязателен, без него будет `SecurityException`. Его нельзя
получить через диалог разрешений внутри приложения — Android требует
именно ADB (или root-shell) для `WRITE_SECURE_SETTINGS`. Это разовая
операция при подключении часов к компьютеру.

После этого открой приложение на часах и нажимай на нужный DPI.
Изменение применяется мгновенно, без перезагрузки.

## 2. `xposed-module` — точечная подмена DPI для одного стороннего APK

Это то, что нужно для "квадратизации" — чтобы конкретное телефонное
приложение уменьшилось и вписалось в маленький экран часов, не трогая
системный DPI для всего остального.

**Требует root + установленный LSPosed framework на часах.**
Без этого технически невозможно повлиять на рендеринг чужого APK —
Android не даёт одному приложению лезть в Resources другого без
системных прав уровня модуля Xposed/LSPosed.

### Настройка

Перед сборкой открой `DensityHook.kt` и укажи:
- `TARGET_PACKAGES` — package name приложения, которое хочешь ужать
  (узнать: `adb shell pm list packages | grep часть_имени`)
- `TARGET_DENSITY` — целевой DPI, обычно 120–160 для сильного уменьшения

### Установка

```
adb install xposed-module-debug.apk
```

Дальше — в приложении **LSPosed Manager** на часах:
1. Найти модуль "DPI Changer" в списке модулей
2. Включить (toggle)
3. В "Scope" отметить целевое приложение (то же, что в TARGET_PACKAGES)
4. Перезапустить целевое приложение (или сами часы для надёжности)

## Сборка

### Вариант А — есть компьютер
Открой корень проекта в Android Studio (или собери через
`./gradlew assembleDebug` при настроенном Android SDK) — соберутся оба
модуля, `app-debug.apk` и `xposed-module-debug.apk` появятся в
`*/build/outputs/apk/debug/`.

### Вариант Б — только телефон, без компьютера (GitHub Actions)

В проекте уже есть `.github/workflows/build.yml` — облачная сборка,
всё делается с телефона через браузер или приложение GitHub.

1. Создай аккаунт на github.com (если нет).
2. Создай новый **пустой** репозиторий (New repository), например `DpiChanger`.
   Не добавляй README при создании — репозиторий должен быть пустым.
3. На странице репозитория: **Add file → Upload files**.
   Загрузи содержимое распакованной папки `DpiChanger` (все файлы и
   папки, включая скрытую `.github`). Мобильный браузер обычно
   позволяет выбрать сразу папку/несколько файлов через "Choose files".
   Если браузер не даёт загрузить скрытую `.github` папку — открой
   репозиторий в GitHub, зайди в раздел **Actions**, там будет кнопка
   создать workflow вручную, и вставь туда содержимое `build.yml`
   через веб-редактор (Add file → Create new file →
   `.github/workflows/build.yml` → вставить содержимое).
4. Commit changes.
5. Перейди во вкладку **Actions** репозитория — сборка запустится
   автоматически после коммита (или нажми "Run workflow" вручную,
   если видишь такую кнопку).
6. Подожди 2–5 минут, пока идёт сборка (зелёная галочка = успех).
7. Открой завершённый запуск → внизу страницы раздел **Artifacts** →
   скачай `app-debug-apk` (и при желании `xposed-module-debug-apk`).
   Внутри — сам `.apk`, готовый к установке.
8. Скачанный APK можно установить на часы напрямую (если на часах
   включена установка из неизвестных источников) или через
   `adb install` с любого компьютера позже.

## Важно про "квадратизацию" в целом

Даже с хуком плотности приложение может вылезать за пределы экрана
часов из-за жёстко заданных layout-размеров, системных жестов навигации
(back gesture снизу) или предположений про соотношение сторон экрана.
Хук решает масштаб, но не гарантирует идеальную посадку под любой APK —
это зависит от того, как исходное приложение сверстано.
